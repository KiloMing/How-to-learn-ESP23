# 综合项目：采集与远程控制小终端

第一版只做一条完整链路：

```text
STM32 采样 / LED或PWM输出 ←UART→ ESP32 ←MQTT→ Linux broker + 记录程序
                                                        ↓
                                                  ROS2桥接（扩展）
```

STM32 接手头已有传感器；没有时先用 ADC 电位器。ESP32 转发数据和命令，Linux 保存带设备编号、序号、时间和单位的数据。命令只调整采样周期和 LED/PWM 输出。

## 分四次做

| 小版本 | 本次任务 | 通过再继续 |
|---|---|---|
| V1 串口 | STM32 采集，ESP32 显示；先完成协议表 | 1000 帧计数正确，CRC 错误和半帧可恢复 |
| V2 联网 | 上报 MQTT，Linux 落盘；回传配置命令和结果 | 日志能串起 command_id、串口序号、执行 ACK；不能只凭发布成功说执行成功 |
| V3 异常 | 断网、重启 broker、串口断开、两板重启、非法命令 | 本地超时保护有效；恢复后不执行旧命令；队列和重试次数有上限 |
| V4 交付 | 补接线图、版本、依赖、构建步骤和测试记录 | 干净克隆后可照文档构建，连续三次冷启动可复现 |

## 开始前写下指标

- 遥测先按 1Hz，带递增序号；连续运行 1 小时，记录接收总数、缺号和重复数量，不能只写“很稳定”。
- 正常局域网下发送 100 条控制命令，Linux 用同一单调时钟测发送到执行 ACK 的往返时间；目标 1 秒内，无应答单独记为失败。不能拿两台未同步设备的时间戳相减当单程延迟。
- 本地控制超时 500ms，以 STM32 收到最后一条有效控制命令为起点；测实际输出回落时间。断网重连不自动恢复旧 PWM。
- 断网 60 秒，本地采样继续；遥测队列满时丢最旧数据并累计丢弃数，控制命令不能无限缓存。
- 网络恢复且 broker 可用后目标 30 秒内恢复上报；分别重复断网、重启 broker、断串口各 3 次。
- 记录开始、中间、结束的空闲堆、栈剩余量和复位原因；发现持续增长或下降趋势，先定位再标完成。

上面是学习用的初始指标。要改就在测试前写原因和新指标，测试后保留实际结果。

## 交付放什么

后续在 `projects/telemetry_terminal/` 放 ESP32 工程、STM32 工程或明确的源码提交链接、Linux 接收程序、协议说明、接线表和测试日志。每个工程自己有 README，注明运行目录和命令。现在不建空壳源码，也不提前写“测试通过”。

## ROS2 扩展

主线验收后，Linux 端把新遥测转成 ROS2 消息，参数或服务转成带 command_id 的配置命令。声明数据单位、时间含义和超时状态；数据停更时标为无效，不能继续发布旧值冒充实时数据。再用 rosbag 记录并对照原始协议日志。

蓝牙、OTA、低功耗和云端界面留作后续，一次选一个扩展。
